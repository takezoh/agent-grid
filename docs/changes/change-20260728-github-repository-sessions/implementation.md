# Implementation

## Ownership and order

1. Protocol/domain foundation defines identities, preparation state, and the exact-version surface before I/O.
2. Client hosts implement the fixed OAuth App device flow and validated retained catalog while the server implements authenticated lease/clone boundaries.
3. Durable preparation, clone publication, restart reconciliation, and bounded admission land before repository environment reuse.
4. Fleet projection and the shared accessible picker consume only credential-free server/host snapshots.
5. Fidelity triples and the full flag-day consumer matrix close delivery.

## Fixed seams

| Boundary | Owner | Replaceable seam |
|---|---|---|
| GitHub OAuth and repository API | each client host | injected HTTP transport, clock, random source, credential/cache store |
| credential transfer and git | server API / platform clone service | lease clock/store, process runner, peer/nonce broker, fake git |
| preparation filesystem/process | host runtime / reducer | pure event/effect table, persistence, filesystem, process group |
| repository devcontainer | host runtime / platform sandbox | durable environment store, sandbox manager, fakedocker |
| UI and host projection | host FleetRuntime / shared SPA | credential-free provider fixture, pure palette reducer, real DOM |

## External dependency triples

| Dependency | Fake | Invariant contract | FakeVsReal / real authority |
|---|---|---|---|
| GitHub authorization | FakeGitHubAuth | GitHubAuthContract | FakeVsRealGitHubAuth; dedicated OAuth App and controlled device-approval account |
| GitHub repository API | FakeGitHubCatalog | GitHubCatalogContract | FakeVsRealGitHubCatalog; controlled account repository set |
| git clone | FakeGitClone | GitCloneContract | FakeVsRealGitClone; configured private fixture repository |
| filesystem/process | FakeFilesystemProcess | FilesystemProcessContract | FakeVsRealFilesystemProcess; host filesystem/process group |
| repository devcontainer | FakeRepositoryDevcontainer | RepositoryDevcontainerContract | FakeVsRealRepositoryDevcontainer; explicitly configured Docker fixture |

Absent T3 authority is an explicit skip. It is never evidence that the success path passed.

## Implementation detail intentionally left free

Only `implementation-detail-standard-library-composition` remains. Direct standard-library composition and reuse of existing wrappers are interchangeable only if the shared counterexample produces the exact same contract observables and verification results. No new dependency may be selected by this plan.
